# Module 00 — BACKLOG (corrections and future work)

> **Purpose:** shared platform work that is registered but not being worked.
> **Read when:** planning core work or triaging a shared-layer finding.
> **Canonical for:** core work items.
> **Do not duplicate:** the boundary rule and invariants (`MODULE.md`).

**Last update:** 2026-11-16

Core items are identified `CORE-NN` and are never mixed with module invariants.

## 2. States

- `new` — registered, not approved, not planned.
- `in progress` — accepted and being worked.
- `accepted` — approved by the owner, not scheduled.
- `blocked` — waits on another item, named in the row.
- `deferred` — postponed behind a named milestone.
- `implemented` — shipped, with the date.
- `moved` — addressed elsewhere; the target identifier owns the work.
- `discarded` — rejected, with the reason.

## 3. Types

- `correction` — restores documented behaviour.
- `improvement` — new capability of the shared layer.
- `restructuring` — internal reorganisation without a behaviour change.
- `security`, `performance`, `docs`, `test`, `tech-debt` — as named.
